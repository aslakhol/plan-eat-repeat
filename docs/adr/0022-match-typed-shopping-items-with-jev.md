# Match typed shopping items with Jev

Typed input that is not exactly a known name-and-note combination is matched by Jev against the Household's Own Items and the Standard Shopping Items for its Shopping Language. This applies to manual additions, the literal autocomplete choice and Usually Have by name. A confident match reuses the Own Item, or saves the Standard Shopping Item's name as a new Own Item, instead of creating a near-duplicate such as "Tomato" beside Tomatoes. Suggestions chosen from autocomplete already name their product and are not matched. Recipe additions keep their word-based resolution for now.

Jev accepts at most 255 options per question, and the candidates exceed that. Following TypeSafe's guidance for large option sets, Own Items and Standard Shopping Items are split into separate chunks of 254 plus a `none` option, and each chunk gets its own question in the same request as the Category Classification question. Questions in a request are answered in parallel, so extra chunks add tokens but little latency. When exactly one chunk finds a confident match, it is used. When several chunks of the same kind do, a second request asks a single question over their winners plus `none`. For input that isn't an exact standard name, the category is always asked in the first request, so an unmatched item never needs another round trip.

A confident Own Item match always wins over Standard Shopping Items, because the Household's own version of a product, such as Tomatoes with the note cherry, is what it buys. Own Items and standard items are therefore never compared in the same question. Input that exactly names a Standard Shopping Item is still matched against Own Items, and only falls back to the standard item when none matches.

A wrong match silently merges one product into another, which is worse than a wrong category. Matches therefore need a confidence of at least 0.9, against 0.4 for categories. A match is saved exactly as the candidate: a matched Own Item keeps its Remembered Shopping Category, and a matched Standard Shopping Item takes its catalog category. Because nothing from the input is carried over, a match must be the same variant: Jev is told that a more specific or more general product, such as cherry tomatoes for Tomatoes, is not a match, so recipes that ask for a particular variant keep it. Both requests share the three-second timeout. Failures, timeouts, `none` answers and uncertain matches create the typed item as a new Own Item, as before.

Standard Shopping Items carry their catalog category again. Input that exactly names one, including an autocomplete choice of a standard name, uses that category without a Jev request. Category Classification is only for genuinely new Own Items.

This supersedes [ADR 0021](0021-classify-new-own-items-with-jev.md)'s statement that resolving input against known Own Items remains outside Jev's scope, and its removal of category inheritance from exact catalog matches.
